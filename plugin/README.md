# STE Assistant — черновик 0.3

В 0.3.4 исправлено ложное устаревание нарезки после экспорта: камеры `snapshot`, стол и предпросмотр слоёв не считаются моделями и не доступны ИИ для удаления. Реальное изменение детали, настроек, G-code или стола по-прежнему требует новой нарезки.

В 0.3.3 исправлена взаимная блокировка экспорта G-code и 3MF: штатные writer запускаются из рабочего потока, а главный поток обрабатывает их запросы миниатюры/проекта. Перед выдачей ссылки проверяется актуальность модели и настроек. После обновления перезапустите STE.

Плагин для STE Slicer 7.10 / Cura API 5. Интерфейс работает в системном браузере, Python-код — внутри слайсера. Внешние Python-пакеты и сборка JavaScript не нужны.

Интерфейс предназначен для браузера на ПК. Раскладка учитывает разные размеры окна настольного браузера.

## Установка

1. Закройте STE Slicer.
2. Через **Справка → Показать папку конфигурации** найдите папку нужной версии. Обычно это `%APPDATA%\steslicer\7.10`.
3. Скопируйте **папку `AIAssistant` целиком** из этого каталога в `plugins` папки конфигурации. Должен получиться путь `plugins/AIAssistant/plugin.json`.
4. Перезапустите STE. Откройте **Расширения → STE Assistant → Открыть чат и настройки**. Название верхнего меню может зависеть от языка приложения.
5. В чате нажмите шестерёнку. Base URL: `https://api.timeweb.ai/v1`; модель: `dashscope/qwen3.8-flash`. Введите API key и сохраните.

В репозитории также есть `tools/install.ps1`. Скрипт устанавливает только в новый каталог, существующий плагин не перезаписывает.

Ключ хранится в preferences STE (`ste_assistant/api_key`). В исходниках ключа нет; браузеру после сохранения возвращается только признак наличия. Пустое поле сохраняет прежний ключ, флажок удаления очищает его. Каждый платный запрос инициирует пользователь; автоматических повторов после сетевой ошибки нет.

## Первый запуск

Исправления 0.3.2: STL/OBJ/3MF принимаются до **64 MiB**, изображения и документы до 24 MiB. Строковые числа и переключатели LLM приводятся к типу настройки STE; запись выполняется в `userChanges` и проверяется чтением значения. Для количества линий стенки используется `wall_line_count`. После завершения нарезки чат получает нативные время и расход; длина нити переводится из метров STE в миллиметры API.

1. В STE выберите **Stereotech Hybrid 530 V5.2.4** и доступный материал.
2. Загрузите STL в STE или прикрепите STL/OBJ/3MF в чате. Для 3MF возможен штатный диалог импорта проекта — завершите его в STE.
3. Напишите: «Прочитай сцену и доступные профили. Подготовь модель к 3D-печати. Сначала объясни предлагаемые изменения». Обязательно сообщите назначение детали и материал.
4. Переписка находится в центре, сохранённые диалоги — слева. Кнопка «Условия» рядом с сообщением позволяет добавить обязательные настройки, ID материала и сохранение размеров. Пожелания в свободном тексте имеют рекомендательный характер. Сцена доступна на отдельной вкладке, вызовы инструментов и счётчик шагов — во вкладке «Разработчикам».
5. Попросите применить параметры и запустить слайсинг. Статус и прогресс появятся справа. После успешного нового слайсинга сохраните 3MF и экспортируйте G-code. Файлы скачиваются из панели «Файлы».
6. Откройте полученный 3MF заново и проверьте настройки, ориентацию и предпросмотр G-code в STE перед использованием.

Поддерживаются только `classic` (3D), `cylindrical` (5D Spiral), `cylindrical_full` (5D). Инструмент `check_5d` разделяет факты сцены и инженерные предположения; точная геометрия удаляемой внутренней цилиндрической области в этом черновике не вычисляется.

## ТЗ из Word или текстового файла

Нажмите **＋** рядом с сообщением, выберите **DOCX** или **TXT** и дождитесь статуса готовности. Можно приложить ТЗ и STL/OBJ/3MF одним сообщением, например: «Подготовь приложенную модель с учётом ТЗ». Файл можно отправить и без дополнительного текста.

Текст Word, включая таблицы, извлекается локально и передаётся модели как справочные данные. Изображения внутри Word не распознаются; их можно приложить отдельно как PNG/JPG. Старый двоичный `.doc` нужно сохранить в Word как `.docx` или `.txt`. TXT поддерживает UTF-8, UTF-16 с BOM и Windows-1251. Максимум — 24 MiB на файл, 120000 символов текста и 8 вложений в сообщении; слишком большой документ отклоняется без скрытого сокращения.

## Продолжение длинной задачи

В версии 0.3.1 ответы LLM принимаются потоком (SSE): плагин читает фрагменты и собирает завершённый ответ перед выполнением инструментов. Если провайдер возвращает обычный JSON вместо SSE, он также поддерживается. Лимит отсутствия сетевых данных — 180 секунд; общий лимит потока проверяется между кадрами и составляет 600 секунд. Сетевой таймаут приостанавливает задачу: нажмите **«Продолжить»** для одного нового запроса без повторного выполнения уже завершённых инструментов. Автоматических платных повторов нет.

Старое сообщение про «лимит 12 шагов» создавал сам плагин. Теперь один ручной запуск допускает до **48 запросов к модели** и **10 минут** между контрольными точками. Локальные инструменты не считаются отдельными запросами к модели. Уже начатый запрос или набор инструментов может завершиться после временной границы.

При достижении границы появится карточка **«Продолжить»**. Она запускает следующий отрезок того же запроса с сохранёнными результатами инструментов. Можно вместо этого отправить изменённую задачу: выполненные действия останутся в контексте. Ошибка провайдера и отмена не запускают автоматический повтор. После перезапуска STE переписка сохраняется, а незавершённый запуск помечается прерванным: продолжение требует нового сообщения пользователя.

Поле ввода остаётся доступным во время работы помощника; отправка нового запроса блокируется до завершения. Во время загрузки вложений отправка тоже заблокирована, чтобы файл не потерялся.

## Что реализовано

- Chat Completions с tool calling и сохраняемыми паузами; PNG/JPG передаются как base64 `image_url`, DOCX/TXT — как извлечённый текст.
- MCP JSON-RPC `initialize`, `tools/list`, `tools/call` по `/api/mcp`. Те же инструменты используются агентом и кнопками интерфейса.
- Чтение/изменение global/extruder settings; выбор режима, профиля и материала; операции модели; запуск/статус слайсинга и нативные writers.
- Формальные жёсткие требования блокируют конфликтные вызовы. Перед слайсингом/сохранением проверяется фактическое значение закреплённых настроек и ID материала. Закрепление требования само по себе не применяет настройку.
- Сравнение 2–3 **наборов настроек** с настоящим последовательным слайсингом внутри STE; отдельные 3MF/G-code; восстановление исходных user overrides. Профили, материалы и положение модели между вариантами не меняются. Применение варианта требует нового слайсинга.
- Локальный сервер: loopback, случайный порт, токен сессии в заголовке, проверки Host/Origin, ограниченные вложения. Токен никогда не передаётся URL query; fragment убирается после открытия страницы.

## Границы проверки

На 23.10.2026 код проверяется на Python 3.5.7 из установленного STE, с локальным тестовым Chat Completions сервером и тестовыми адаптерами. Это не подтверждение реального провайдера Timeweb и полного цикла на всех моделях организаторов. Для Timeweb нужен ваш ключ; импорт/слайсинг/экспорт внутри запущенного STE требуют отдельного сквозного прогона. Отсутствующий API выдаёт ошибку, а неизвестные время/расход не заменяются вымышленными числами.

Диалоги, завершённые обмены с моделью, текст отправленных ТЗ, условия и сведения о результатах сохраняются локально в каталоге данных STE `ste_assistant/history`. При переключении диалогов сцена STE остаётся общей. Возврат в старый диалог не загружает модель и не применяет настройки автоматически. История ограничена 50 диалогами, 32 MiB на диалог и 64 MiB на файл; ошибка сохранения отображается явно, существующий файл не сокращается автоматически. API-настройки плагина сохраняются отдельно в STE и не включаются в историю. Удалённые через инструменты объекты и трансформации используют штатные undo operations STE.

При отмене новые agent tool calls прекращаются. Поток прерывается при следующем чтении; ожидание очередных сетевых данных может длиться до 180 секунд. Файлы результатов сохраняются в каталоге данных STE `ste_assistant/outputs`; они доступны через панель скачивания. Вложения текущего запуска удаляются при штатной остановке помощника.
