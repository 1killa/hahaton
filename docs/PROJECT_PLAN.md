## 1. Идея продукта

Разработать ИИ-помощника по подготовке 3D-печати внутри STE Slicer. Пользователь описывает, какую деталь и для чего хочет напечатать, прикладывает модель, а помощник переводит эту задачу в конкретные настройки слайсера.

Результат для пользователя:

- настроенный проект 3MF;
- G-code, полученный слайсингом;
- понятное объяснение выбранного режима, профиля, материала, ориентации и параметров;
- расчётное время печати и расход материала.

Пользователь проходит весь путь от задачи до файлов для печати в одном диалоге.

## 2. Сценарий пользователя

Пример запроса: «Это кронштейн под нагрузку. Печатать PETG, желательно без поддержек». К запросу прикреплён STL-файл.

Помощник последовательно:

1. Получает сведения о модели, выбранном принтере, материале и текущих настройках.
2. Уточняет существенные детали — например, направление нагрузки, если без этого трудно выбрать ориентацию.
3. Подбирает режим печати и доступный профиль, определяет ориентацию и необходимые изменения настроек.
4. Применяет изменения через инструменты слайсера. В чате видно, что именно было изменено.
5. Запускает слайсинг, показывает прогресс, расчётное время печати и расход материала.
6. Предлагает сохранить проект 3MF и G-code, объясняет выбор параметров.

Пользователь может скорректировать результат следующим сообщением, например: «Сократи время печати» или «Измени ориентацию».

## 3. Логика принятия решений

Сочетать возможности LLM с проверяемыми данными самого слайсера.

- LLM отвечает за понимание запроса, уточняющие вопросы и составление последовательности действий.
- Доступные материалы, профили, параметры и состояние сцены помощник получает из STE Slicer.
- За основу берётся существующий профиль, который затем корректируется под задачу.
- Перед применением инструмент проверяет аргументы: существует ли настройка, допустимо ли значение, выбран ли объект.
- После выполнения инструмент возвращает фактический результат. Ответ пользователю опирается на этот результат.
- Выбор между 3D, 5D Spiral и 5D обосновывается задачей и возможностями выбранного принтера.

Изменения должны быть видны пользователю. Ошибки инструмента или слайсинга должны отображаться как ошибки, а завершение операции — подтверждаться результатом STE Slicer.

## 4. Архитектура

| Часть | Назначение |
|---|---|
| Чат в браузере: HTML, CSS, JavaScript | Принимает текст, изображения и модели; показывает диалог, действия помощника, прогресс и результаты |
| Python-плагин STE Slicer | Запускает локальный HTTP-сервер и связывает интерфейс со слайсером |
| Агент с LLM | Обрабатывает запрос, вызывает инструменты, анализирует ответы и объясняет решения |
| MCP-инструменты | Читают и меняют настройки, управляют моделями, запускают слайсинг и сохраняют файлы |

Общий поток:

Пользователь → SPA в браузере → локальный Python-плагин и агент → LLM → вызовы MCP-инструментов → API STE Slicer → проект 3MF и G-code.

### Ограничения из задания

- Python 3.5-совместимый код и PyQt5 из выданного дистрибутива.
- Формат плагина Cura 3.6 / STE Slicer, в `plugin.json` указано `"api": 5`.
- SPA открывается в системном браузере и взаимодействует с плагином через локальный HTTP-сервер. Для событий можно использовать polling или WebSocket.
- Подключение к LLM — OpenAI-совместимый Chat Completions API с tool calling. Изображения передаются как `image_url` в base64.
- Ключ вводится в настройках плагина и хранится в настройках приложения. В исходниках и этом файле ключей нет.
- MCP реализуется самостоятельно в необходимом объёме: JSON-RPC 2.0, `initialize`, `tools/list`, `tools/call`. Официальный Python MCP SDK внутри старого Python слайсера не используется.
- Изменения сцены, настроек и запуск слайсинга выполняются в главном потоке Qt через `app.callLater(...)`.
- Разрешённые режимы: **3D (`classic`)**, **5D Spiral (`cylindrical`)**, **5D (`cylindrical_full`)**.
- Основной профиль испытаний: **Stereotech Hybrid 530 V5.2.4**.

### Обязательные группы инструментов

1. **Настройки и профили:** чтение и изменение глобальных настроек и настроек экструдера; получение списков профилей качества и материалов; выбор, создание и сохранение профиля; переключение режима печати.
2. **Модели:** загрузка файла в сцену, список объектов, перемещение, поворот, масштабирование, автоматическая расстановка, удаление, получение габаритов.
3. **Слайсинг и сохранение:** запуск, статус и прогресс, время печати и расход материала, экспорт G-code, сохранение проекта 3MF.

### Согласованные собственные фичи

Выбраны пользователем 23 октября 2026 года. Черновая реализация добавлена в `hahaton`; реальные измерения вариантов и проверка поведения 5D в слайсере остаются частью сквозного испытания.

**1. Автоматическое сравнение вариантов печати.**

- По запросу пользователя помощник готовит 2–3 допустимые конфигурации, например с приоритетом времени или экономии материала.
- Для каждого варианта выполняется настоящий слайсинг в STE Slicer.
- В чате сравниваются расчётное время печати, расход материала и изменённые параметры. Числа берутся из результатов слайсера.
- Исходное состояние и варианты сохраняются раздельно; пользователь может применить выбранный вариант.
- Расчётную прочность и качество поверхности не заявляем подтверждёнными только на основании ответа LLM или времени слайсинга.

**2. Закреплённые требования и проверка противоречий.**

- Существенные условия пользователя фиксируются отдельно: например, материал PETG, сохранение размеров, запрет поддержек.
- Обязательные условия отделяются от пожеланий; неоднозначные условия уточняются у пользователя.
- Перед изменениями помощник проверяет, соблюдаются ли закреплённые требования.
- При обнаружении конфликта объясняет его и предлагает возможные компромиссы. Обязательное условие не изменяется без согласия пользователя.
- Демонстрационный сценарий: закрепить материал и размеры, затем попросить сократить время печати — помощник меняет только разрешённые параметры.

**3. Специализированная проверка подготовки к 5D.**

- Помощник собирает сведения о форме детали, нагрузках, сопрягаемых поверхностях и основании для печати; измеренные характеристики модели отделяет от ответов пользователя.
- Проверяет выбранный режим и связанные с ним параметры, включая основание и `Base Diameter`, и объясняет их влияние на подготовку модели.
- Для 5D Spiral предусматриваем предупреждение об исключении из модели области внутри цилиндра, заданного `Base Diameter`, с проверкой поведения в выданном дистрибутиве.
- Предполагаем показывать влияние выбранного основания и диаметра до получения итогового G-code. Способ геометрической проверки и отображения уточняется после изучения API.
- Методическая основа: [режимы печати Stereotech](https://wiki.stereotech.org/ru/steslicer/five-axis) и [памятка по выбору параметров](https://wiki.stereotech.org/ru/memo/print-parameter).

Остальные обсуждавшиеся идеи — подбор под лимиты времени и материала, групповой откат, паспорт подготовки и библиотека подтверждённых печатей — в выбранную тройку не включены. Отдельно не обещаем их в текущем объёме.

## 6. Проверка результата и пользы

Экспертам показываем один сценарий целиком:

- исходная модель и запрос пользователя;
- вызовы инструментов и их результаты;
- изменения настроек и сцены в STE Slicer;
- процесс слайсинга;
- итоговые файлы 3MF и G-code;
- объяснение выбранных параметров.

Сохранённый 3MF повторно открываем, чтобы проверить настройки и расположение объектов. Результат слайсинга проверяем в STE Slicer.

Измеряем время подготовки вручную и через помощника. Конкретное ускорение заявляем после измерений.

Эталонные 3MF находятся у жюри и участникам не выдаются. Близость к эталонам до оценки жюри не считаем подтверждённой.

Ориентиры по критериям оценки: работоспособность прототипа, решение основной проблемы, простота установки и сопровождения, связанные с кейсом новые идеи, удобство интерфейса, решение второстепенных проблем и обоснование продукта через анализ аудитории и аналогов.

## 8. Текст для первого чекпоинта

Мы предлагаем ИИ-помощника внутри STE Slicer, который помогает подготовить деталь к печати по описанию задачи. Пользователь загружает модель и сообщает требования, а помощник подбирает профиль, материал, режим печати, ориентацию и настройки, после чего запускает слайсинг.

LLM будет управлять слайсером через MCP-инструменты. Пользователь увидит действия помощника, их результаты и объяснение выбранных параметров. На выходе он получит проект 3MF и G-code.

Собственные возможности нашего решения — автоматическое сравнение вариантов по результатам слайсинга, контроль закреплённых требований пользователя и специализированная проверка подготовки к 5D. Они помогут выбирать подходящий вариант, понимать компромиссы и обнаруживать ошибки до печати.

Наш первый приоритет — продемонстрировать весь этот путь на одной модели, затем проверить решение на полном наборе организаторов. Ценность продукта мы видим в сокращении ручной настройки и в том, что начинающий пользователь сможет получать результат, одновременно понимая логику подготовки к печати.
