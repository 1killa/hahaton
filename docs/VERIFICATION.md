# Проверка черновика STE Assistant

## MVP 0.4.2 — пять кнопок сцены, 25 октября 2026

Исправлена общая причина отказа кнопок «Обновить сцену», «Проверить 5D», «Нарезать», «Сохранить 3MF» и «Экспорт G-code»: слот с QVariant получал QJSValue, после чего worker падал с `'QJSValue' object is not iterable`. Слот принимает QVariantMap, а обычный Python dict копируется в GUI-потоке до передачи worker. HTTP API, браузерные исходники и кнопки скачивания готовых файлов не менялись.

Новый сценарий в tools/host_native_smoke.py нажимает каждую настоящую QML-кнопку на Qt 5.10 и проверяет цепочку HTTP → AgentSession → ToolRegistry, имена инструментов и аргументы (включая filename для 3MF/G-code). Предупреждения 5D и короткий результат действия видны под кнопками. До исправления первая кнопка воспроизвела ошибку; после исправления прошли все пять. Журналы: .runtime/scene-buttons-red.log и scene-buttons-green.log.

Все операции в этом прогоне изолированные: адаптер тестовый, экспортирует явно помеченные фикстуры, настоящие модели пользователя, платный LLM и печать не используются. Реальная нарезка пользовательской детали в этом прогоне не заявляется. Проверка уже работающего скачивания результатов также прошла.

Приоритет MVP зафиксирован в плане проекта и отдельной заметке памяти по прямому указанию пользователя. Изменения ограничены текущим сбоем и видимой обратной связью кнопок.

Общий набор на штатном Python STE: **172 теста, 171 прошёл, 1 symlink skip**, .runtime/scene-buttons-final-host-tests.log. Перед публикацией повторён тот же полный набор: .runtime/github-final-host-tests.log, результат тот же. Архив dist/hahaton-0-4-2-native.zip проверен: 24 записи, все 22 исходных файла плагина совпадают с рабочей копией; три веб-хеша сохранены. Скомпилированные Qt-кэши .qmlc/.jsc исключены из Git, упаковки и установки. SHA-256 чистого архива: 218f0bfdb5f4515b4177ac458192904e24d5445bce1bb7b5ac4bc71a16d58f2f.

## Исправление 0.4.1 — STL в окне выбора вложения, 25 октября 2026

Ошибка воспроизведена на Qt 5.10 из STE: исходная строка фильтров с одиночными `;` давала активные шаблоны только `*.png *.jpg *.jpeg`. Исправлены разделители групп на `;;`, по умолчанию выбрана общая группа всех поддерживаемых файлов.

`tools/host_attachment_picker_smoke.py` проверяет настоящий QFileDialog/QFileSystemModel на изолированных файлах: STL и uppercase STL, OBJ, 3MF, DOCX, TXT, PNG/JPG; общая группа и три отдельные категории. До исправления — воспроизведено скрытие STL; после — HOST_ATTACHMENT_PICKER_SMOKE_PASSED. Журналы: .runtime/attachment-picker-red.log и attachment-picker-green.log. Этот сценарий проверяет фильтр реального Qt, не обращается к LLM и не выполняет слайсинг.

Дополнительная проверка подтвердила наличие всех 8 файлов в строках реального QFileSystemModel; снимок окна — .runtime/attachment-picker-fixed.png, журнал — .runtime/attachment-picker-rows-green.log. Общий набор на Python STE: **172 теста, 171 прошёл, 1 symlink skip**, .runtime/attachment-picker-final-host-tests.log. Архив dist/hahaton-0-4-1-native.zip проверен: 25 записей, 23 файла плагина совпадают с исходниками, все три веб-хеша неизменны. SHA-256 архива: fa6486730b0f1c5ebe667c2c3f35c1c820663db764414d8dc4cb227b45b3b632.

Версия **0.4.1 установлена**, 23 файла проверены по SHA-256; резервная копия — .runtime/backups/AIAssistant-pre-0.4.1-20261025-011302. Настройки, диалоги и проекты не менялись. Для загрузки исправленного Python-кода требуется перезапуск STE.

| Native export boundary | Проверены правильный workspace writer, текстовый G-code writer, atomic replace, сохранение прежнего файла при ошибке и запрет stale generation после изменения сцены/настроек |
| 5D | Тесты проверяют фактический Base Diameter и габариты, отсутствие выдуманного диаметра при недоступном API, предупреждения для Spiral и разделение фактов/предположений |
| Проверка финальной упаковки | `--require-results` ожидаемо отказывает при отсутствии реальных результатов; обычный режим создаёт только явно обозначенный черновой ZIP |

На Windows сетевые и файловые тесты запускались вне ограниченного sandbox с временным каталогом **внутри `.runtime/` проекта**. Причина — sandbox блокирует loopback sockets и очистку своего системного TEMP; продуктовые ограничения сети не ослаблялись.

Вызов заменён на `os.path.join(Resources.getDataStoragePath(), "ste_assistant")`, соответствующий API установленной версии. `results/` содержит только инструкции. Настоящих конкурсных `project.3mf`, `result.gcode` и скриншотов переписки с реальным слайсингом пока нет. `docs/screenshots/demo-ui.png` и `settings.png` — исключительно скриншоты интерфейса DEMO; настоящий ключ на них отсутствует.

## Решения после review

- Замечания о stale G-code, пустой сцене, atomic writer, native build plate и пробельном ключе исправлены и покрыты регрессиями.
- Обычное отсутствие `scope` в закреплённом правиле трактуется как global; значение и extruder=0 явно нормализуются при сохранении. Это документированный default, аналогичный интерфейсу, а не необеспеченное требование.
- Автоповторов платных запросов нет. Demo может обращаться к реальному LLM только после ввода ключа и отправки сообщения пользователем; печать/экспорт в Demo недоступны.
