# Чат, документы ТЗ и продолжение длинных задач

Пользователь просит объяснить обрыв на 12 шагах, принимать ТЗ в Word/TXT,
улучшить интерфейс и убрать технические логи из переписки.

Сохраняем существующий Python 3.5/stdlib плагин и локальную SPA. Документы
извлекаются локально, их текст передаётся модели как данные вложения. Поддержка
Word означает DOCX; двоичный DOC отклоняется с подсказкой сохранить DOCX/TXT.
Исходный пример ТЗ не изменяется. Текст документа ограничен 120000 символами;
превышение отклоняется явно, без незаметной обрезки.

Выбранные решения: 48 обращений к модели и 600 секунд на один ручной запуск;
по достижении границы — сохранённая пауза и кнопка «Продолжить». Завершённые
инструменты не повторяются. Новый запрос после паузы сохраняет предыдущие
результаты в контексте и начинает новый ход. Ошибка API и отмена не вызывают
автоматического повтора. Состояние сессии остаётся в памяти процесса.

Журнал сохраняется в свёрнутом блоке справа, вне переписки. В чате — сообщения,
ответы и понятные ошибки. Поле ввода остаётся доступным при работе агента.
Интерфейс получает читаемую центральную колонку, русские подписи, типы вложений,
состояние загрузки. По уточнению пользователя интерфейс предназначен только для
браузера на ПК; сохраняется адаптация к разной ширине окна, отдельная мобильная
раскладка исключена.

Альтернативы: только увеличить число 12 (не решает потерю хода при обрыве);
бесконечный цикл (нет ограничения расходов/зависания); отдельный сервер разбора
Word (ненужные зависимости для STE). Выбрано ограниченное продолжение и stdlib.

Проверка: регрессии агента/HTTP/парсера, реальный пример DOCX, браузер при разных
размерах окна ПК, suite на штатном Python 3.5. Платные запросы и настоящий
слайсинг для проверки этого изменения не нужны.
